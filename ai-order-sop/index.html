AI 接单能力 · 蒸馏方案

让 AI 交付可接单的制作资料，靠证据闭环，不靠提示词自信。

以 HW73005-L2000 R04、工程师参考制作图及最新审图意见为回放材料。面向未来每单都不同的书桌、展柜、电视柜、衣柜及照明陈列需求：一个 Skill 先读资料、生成产品树，只追问决定方案的少量特性问题，再组织出图和自检。

公开方法论三轮团队审查手机端可读R04 仍未生产放行

核心架构

1 个 Skill
＋ 1 条有状态流程
＋ 独立校验器

Skill 管判断，流程管状态，校验器管确定性错误；工程和工厂证据决定能否放行。

01 / 判断

现有 Skill 有方向，单独使用不足以兜底。

当前 Skill 已要求三视、爆炸、逐件追溯和 1:1 下料。R04 的问题证明：写进说明 ≠ 生成器执行 ≠ 最终文件通过验证。要补的是能拦住错误交付的流程和证据，不是单纯延长提示词。

AI 应主动做

读取源图、识别结构风险、提出候选方案、生成图纸和清单、逐件核对、修复可证实的漏项，并在证据不足时降低交付等级。

不能由文件自证

桌面长期抗翘、焊接与挂具实际可行、材料回弹、接收方 CAD 行为及首件装配。它们需要约定工况、独立审查或真实试验记录。

02 / R04 反例

把工程师反馈变成可回放的失败样本。

以下是图纸和数据可支持的事实；结构风险只标为待验证，不把工程师建议直接当成唯一做法。查看 R04 图册。

E01 · 需求丢失桌面四周无翘角

源图已写明目标，并建议葫芦孔与角码；R04 采用 8 点 M6 底部固定。应核周边约束与使用工况。葫芦孔是候选方法，不是通用强制件。

E02 · 部分闭合桌腿不是“完全没封板”

S03A 壳高 877 mm，S03B/S03B-P 内端封板高 777 mm，另有底封板。顶部斜切区域的闭合、进线与焊接仍要审。

E03 · 装配表达轴测不能冒充爆炸图

A01 有三视与成品轴测；A03 有底部安装轴测，却没有全桌构件实际分离、件号覆盖和装回关系。参考 F02 有爆炸关系，但件表是占位符。

E04 · 对外交付内部有材质，正式表却缺列

R04 正式 XLSX 的部件页未列材质、厚度、表面处理；内部 BOM 存在材料字段也不能代替工厂拿到的表。W01 的饰面说明还未统一。

E05 · 工艺缺口喷粉页缺挂具方案

F01 展示部分件数与泛工艺注释，没有逐件尺寸、挂点或夹持面。工程师要求喷粉图排在末尾，可在本单目录或分包顺序落实，不必删除电气页。

E06 · 比例语义三个“1:1”不可混算

独立激光 DXF 是毫米原尺寸几何；PDF 零件页有缩比视图。Model 几何、Layout 视口和可打印的 1:1 纸图必须分别标注、分别验证。

更隐蔽的错误：内部 BOM 有 10 个部件的 30 个三视页码字段与现版图页不一致，仍引用旧节点号；现有打包校验主要核页数、实体数和哈希，没有拦住语义错位。正式交付包与内部生成源都要检查，且不能由同一生成器只检查自己的输出。

03 / 工程师图纸模板

先看总成，再按主体逐组展开，喷粉件图收尾。

以下顺序是工程师给出的桌类制作图模板，已收录在单入口 Skill 的桌类参考中。逻辑图类可占一页或连续多页，但不能用轴测图冒充爆炸图；每组主体图后紧跟本组拆件图。配套椅、灯光、喷粉仅在订单确有相应对象或工序时启用。展柜、电视柜和衣柜沿用共性骨架，按自己的产品树替换子总成。

  1. 整件三视图＋轴侧图首页给正、俯、左/右侧视和轴侧图；标主要材质、各主体数量。涉及灯光时同页注明供电电压与色温（K），并与电气页、BOM 一致。
  2. 整件爆炸图＋零部件材质第二组用真实分离关系标件号、数量和装回方向；逐件标注材质，并能从正式 BOM 双向找到对应行。
  3. 桌面三视图＋轴侧图给桌面分总成的正、俯、左/右侧视与轴侧图，标尺寸、材料、固定接口和本组件号。
  4. 桌面零部件拆解图紧接桌面主体图，逐件给加工所需视图、材料、尺寸、数量及孔槽/连接关系；不可跳到其他分总成后再补。
  5. 桌体三视图＋轴侧图，或桌体爆炸图选择能解释支承、腿、围板和接口的一种主体表达；选爆炸图也不能省掉制造件必需的成型三视。
  6. 桌体及配套椅零部件拆解图紧接各自主体图逐件展开；订单含椅子时，为椅子建立主体图及其紧随的拆件组，不把不存在的椅件塞入本单。
  7. 其他必要工艺图焊接、木作、五金、电气及灯具安装按适用工序编排，保持件号、材料和数量与主体图同版。
  8. 零部件喷粉图置于图册末尾逐件标喷粉件号、数量、完整尺寸、可见面、遮蔽与挂点/夹持面；无喷粉工序时记录“不适用”，不生成空白末页。

机器验收口径：冻结图页清单后核首页/第二组类型、每个主体图与拆件图的相邻关系、末尾喷粉组、件号及数量/材质/尺寸字段；灯光存在时核电压与色温。校验最终 DWG/PDF 和正式 BOM 的实读内容，读不到字段标 UNVERIFIED，不拿生成器清单自证。

04 / 系统设计

一个 Skill 接单，产品树决定本单图纸。

用户只需进入一个 Skill。它从来源构建“整件→子总成→零件→工序”产品树，再组合共性骨架和条件模块；Runner、出图工具与校验器是后台能力。桌、柜、木作、钣金、喷粉、电气和照明按实际结构启用，不把 R04 的 8 点 M6 或桌类页序硬编码给所有订单。

01 · Skill唯一接单入口

先读订单和图纸，识别子总成及特性模块；只对结构、材料、接口、报价或安全的关键未知集中追问，再决定出图路径与交付等级。

02 · Workflow管状态

冻结订单输入，维护需求—接口—零件—工序图谱、问题单、版本和交付等级。修改一个件号后重验受影响链路。

03 · Validators拦确定性错误

独立回读 PDF/DWG/XLSX/DXF；检查材料、厚度、数量、页码、节点号、1:1、轮廓、孔槽、镜像及成型—展开同版。

04 · Reviewer挑工程缺陷

与生成过程隔离，只看冻结输入和实际交付；审受力路径、装配、维修、喷粉挂具、线缆及缺失条件。

05 · 实物证据决定放行

记录接收方 CAD 操作、同材试折、工装、喷粉试挂与首件结果。数学计算和渲染预览不得写成已实测。

关键防错防止同源共错

同一个 JSON 生成所有文件，可能让所有文件一致地错。用独立读取器、参考约束和接收方行为交叉验证最终件。

每项要求保存来源类型、文件哈希与图页/实体位置、权威级别、状态（明确／推算／候选／未知／冲突／占位）、适用件号与验收方法。关键材料拆成基材、饰面、阻燃等级、厚度和表面处理；验证记录保存工具版本、测量值、输入输出哈希及执行人。这样“参考图占位”不会被继承为真实 BOM。

共性骨架固定，特性模块按单组合

每单共性总装→爆炸→逐组拆件

多零件产品有总装三视与轴侧、真实爆炸；沿产品树深度优先排列主体图和紧随的零件图，正式 BOM、件号和工序与图册同版。

条件模块需求出现才启用

展柜的搁板/玻璃/展示载荷，衣柜的门抽/挂衣/防倾倒，书桌的走线，照明的电压/色温/散热，喷粉的挂具等各自生成图页与 gate。

未知项只问改变决策的事

先查已有资料；仅当缺项会改变结构、材料、价格范围、接口或安全时，每轮集中 1–3 问，给可选方案、影响与阻断等级。其他部分继续制作。

追问例子：带灯书桌若图里已给灯槽，就不再问“要不要灯”；只问未明确的电压、色温及驱动位置。展柜若展示物重量未定，先完成外形和空间图，再问设计载荷及玻璃/搁板支承。衣柜若壁固定条件不明，先完成布局，再问安装基体与防倾倒方式。设计中出现新分歧再问，不要求开工前填完所有字段。答复记录来源、版本及影响件号，回写后只重验相关链路。

问题交由用户指定的结构接单人答复；尚未授权对外联系时，Skill 生成可转发的问题单，不自行发送。

05 / 接单流程

每一关交出证据，失败只阻断受影响范围。

状态机以“件号 × 工序 × 交付等级”为最小判定单元；喷粉挂点未定，不该阻止有依据的条件报价，但不能交喷粉生产文件。局部阻断要沿接口与父总成关系传播，涉及整桌安全时升级为整单阻断。所有等级由程序根据证据计算，不由 AI 自述。

G0 / 输入订单与来源冻结

版本、单位、适用品类、客户目标、参考图和冲突列表。

G1 / 需求提取产品树

每条要求落到总成、件号、接口、工序或显式未知；自动辨认共性与条件模块。

G2 / 工程推演并少量追问

先查来源、再问阻断决策的特性参数；连接、承载、闭合、装配、维护和线缆继续推演。

G3 / 出图本单图页清单

总装→爆炸→按产品树逐组主体/零件→适用工艺；图册、BOM、下料共享件号。

G4 / 机器校验独立回读

实读最终 PDF/DWG/XLSX/DXF 的几何和跨文件引用。PDF 文本若转路径，改用独立 OCR 与逐页视觉定位；读不到的字段标未验证。

G5 / 独立审查反向找错

审图者按源约束、工艺、实际文件找漏项与错误放行。

G6 / 实物工厂与首件证据

接收方开图、材料与工装参数、试折、试挂、装配和功能。

G7 / 交付分级封包

报价包不含生产 DXF；审核包列未决项；放行包附真实记录。

变更传播：材料、孔位、固定方式或工艺一改，自动找出关联的图页、BOM 行、下料、价格与验证记录；旧证据失效后必须重验，不能靠复制上一版“已通过”。

最小数据合同示例：源图要求“桌面四周无翘角” → W01 桌面与支承接口 → A01 总装 / W01 零件页 / 固定工序 → 最终 DWG 孔位、正式 BOM 材质和约定工况记录 → 抗翘约束 gate。缺工况或支承验证时结果为 UNVERIFIED，阻断制造审核完整性及生产放行；报价只允许列为明示假设。

06 / Workflow 如何运行

Skill 给判断规则，Runner 串步骤，Validator 决定能否过关。

单入口 custom-furniture-production Skill 已建第一版；接单 Runner 尚未写成可执行程序。Skill 是 Codex 读的工作说明，能让它提取产品树、少量追问、选择适用规则并调用工具；它本身不会持久保存订单状态，也不能可靠地判定最终 CAD 文件。第一版 Runner 宜用本地 CLI 启动一单，成熟后再接任务队列或界面。

01 · 订单输入冻结一份订单

order.yaml 记录客户目标、图纸来源、数量、材料、工艺、交付等级、版本及未知项；原始文件哈希不随生成稿改写。

02 · 动态规则组装本单模板

Skill 现有桌类参考；未来机器 profile 要把通用三视/爆炸骨架与本单的柜体、门抽、陈列、照明、喷粉模块组合成图页清单。

03 · Runner执行 G0–G7 状态机

按依赖启动需求提取、工程推演、出图与校验，保存运行 ID、输入/输出哈希、问题单及每个 gate 的 PASS/FAIL/UNVERIFIED。

04 · 生成器产出同版文件

从冻结件号和图页清单生成 DWG、PDF、正式 BOM 与适用的 DXF；图页顺序是生成输入，不靠最终人工拖页补救。

05 · 独立校验器回读最终交付件

另一路读取 DWG/PDF/XLSX/DXF，校对页序、三视、件号、材质、数量、尺寸、电压/色温及跨文件关系；文本转路径时用独立 OCR 与视觉定位。

06 · Gate 与封包只输出证据允许的等级

失败或缺证定位到件号/工序并沿接口传播，自动重验受影响链路；报价、制造审核、生产放行各有独立出口，实物证据由接收方补录。

串联动作：用户调用一个 Skill → Codex 读资料、生成产品树和少量关键问题 → Runner 接收冻结订单与动态图页清单 → 调用出图工具 → 独立校验器回读正式文件 → gate 写状态与问题单 → 按等级封包或回到受影响步骤。每次修订生成新 run，旧验证按输入哈希失效；不得把 R04 的哈希、页码或结论复制到新订单。

最小落地次序：先把共性骨架、工程师桌类模板和条件模块做成机器可读图页清单与 DRW/LED/SPR 规则，在 R04 副本上回放；再接现有出图脚本与状态记录；最后用一张新单做 shadow mode。完成这些之前，页面上的 G0–G7 是设计，不是已经自动运行的流程。

07 / 交付等级

“可接单”先定义可用于哪一步。

选择等级查看硬门槛。报价稿可以带清楚的假设；生产放行不能借用报价假设。

可询价 / 条件报价

让客户和供应商能判断范围及价格区间；不能误用作投料文件。

  • 外形、配置、主要件数和材料等级有来源。
  • 候选材料、成本来源、价格有效期与排除项明示。
  • 冲突和未知项列出对价格、工期的影响。
  • 包内显著标“仅供报价”，机器字段 releaseClass=QUOTE。

材料、数量或成本依据不足以形成有界区间时，状态为 INTAKE/BLOCKED：仅交缺项和价格敏感性，不报数值。报价包不附可直接生产的下料 DXF。

制造审核

工厂能按件审图、给出工艺意见，但仍不是开料命令。

  • 总装、真实爆炸、成型图、工艺图、BOM 与下料双向追溯。
  • 正式 XLSX 含基材、饰面、厚度、表处、数量及图页。
  • 结构和工艺风险有候选方案、工况与待验证方法。
  • DWG/PDF/XLSX/DXF 独立回读，关键语义零冲突。

R04 当前名义处于此档，但本页列出的缺口应关闭后才可称“制造审核资料完整”。

生产放行

制造数据和真实过程参数均已被接收方验证。

  • 审核档缺口清零；材料规格、合格供方与来料验收准则锁定，批次敏感工艺另锁批次。
  • 接收方 CAD 打开、量测、编辑与图纸实读有记录。
  • 适用的试折、喷粉挂具、装配首件和功能测试有结果。
  • 检验方案和适用标准按产品分类与客户要求确认。

没有相应实物或接收证据时自动停在制造审核，不能由 AI 声称已放行。

08 / 本次团队三轮

三轮审查的是方案，不冒充三轮实物验收。

参考图与 R04 审计、现有 Skill/脚本审计、工作流设计三个角色独立起稿，再相互批驳；最后对 HTML 成稿和发布前文件做盲点审查。

ROUND 1 · 已完成

独立证据回放

三路分别审源图与成品、Skill 与生成器、接单架构。以文件内容和工程师微信意见对照，区分缺陷、候选做法及误报。

冻结结论：缺全桌爆炸、正式 XLSX 材料列、喷粉挂具、跨文件语义关口；腿已部分封闭，DXF 已有原尺寸。

ROUND 2 · 已完成

交叉批驳与机制修订

审“一个 Skill 就够吗”、同源共错、参考占位、固定页序、1:1 三种语义与局部阻断。重写为通用状态内核、品类规则包、独立校验和分级交付。

冻结结论：源图的无翘角是目标、角码是候选；机器只判一致性，实物证据另列；报价不被制造缺项整单卡死。

ROUND 3 · 已完成

成稿逆向验收

三路复核事实、Skill 落地性及手机端呈现。发现 PDF 文字路径化、报价缺阻断态、风险传播范围不清、正文偏小和规则合同欠具体。

修订结果：增加独立 OCR/视觉回读、INTAKE/BLOCKED、父总成传播、可执行 gate 样例和盲测停止规则；手机 320–430 px 复核无横向溢出。本轮未验证新订单泛化。

09 / 能力评估

先在 R04 拦住已知错误，再用新订单检验泛化。

R04 与微信反馈只做开发回放集。冻结 SOP 后，未来真实订单按项目、客户和工厂隔离为保留集；同一订单的修订版不得同时出现在训练与盲测侧。盲测不给生成角色工程师结论，由独立审查者标注并裁决分歧。

关键需求召回率

对最终文件实读材料、数量、页码、节点和工艺引用；几何坐标而非仅实体数；1:1 分开核。

把已建的单入口 Skill 接到订单输入、产品树、关键追问、变更传播、分级封包与可追溯问题单。

AI 独立交稿，人工和工厂照常验收；记录严重逃逸、一次接收、返工与人工分钟数。

P3 · 受控自动化逐步减人审

仅对已验证的重复产品族及参数包络开放自动交稿；新结构和异常自动回退审核。
